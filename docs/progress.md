Demonstrated locally on Windows with Git 2.53.0.windows.1: a deliberately stale file stat with unchanged content makes default `git diff --raw` replace the physical index despite `GIT_OPTIONAL_LOCKS=0`, changing its bytes, inode, mtime and ctime. Disabling `diff.autoRefreshIndex` preserves the index but leaves a raw `M` with an unknown worktree OID while numstat and patch are empty; strict joining would yield `METADATA_INVALID`. Requesting raw and numstat together still leaves that mismatch. Git's [diff implementation](https://github.com/git/git/blob/v2.53.0/builtin/diff.c) binds `skip_stat_unmatch` to this config and calls `refresh_index_quietly()` after skipping stat-only changes; that refresh takes an index lock without the optional-lock gate. [Diffcore](https://github.com/git/git/blob/v2.53.0/diff.c) performs the content checks before rename resolution. A copied index with automatic refresh enabled yields consistent empty raw/numstat/patch results while leaving the original index unchanged.

The split-index regression demonstrated another physical mutation: `ls-files`, `status`, `check-attr` and `rev-parse --shared-index-path` freshen the real shared index's mtime/ctime on read, regardless of optional locks. [Git's read-cache code](https://github.com/git/git/blob/v2.53.0/read-cache.c) calls `freshen_shared_index()` unconditionally after reading the split base. An index-file copy alone still reads/freshens the original Git directory's shared file. This mechanism was measured locally, not merely suspected.

The runner therefore isolates all index readers in disposable copies. Split-index/shared files and HEAD are copied to a temporary Git directory with the original common directory for object format/objects/refs; Git converts that copy to a full private index. Actual metadata/diff commands run with the original Git directory, worktree, refs, attributes and conditional configuration, redirecting only `GIT_INDEX_FILE`. This avoids changing `includeIf gitdir` or relative worktree-config behavior. The shared-path probe runs on the split copy, and its locator is mapped back to the real shared file for guarding. Diff pins `diff.autoRefreshIndex=true` for every format and `core.splitIndex=false` so refresh writes materialize only in the copy. Physical guards still inspect the actual index/shared index, refs, configuration, attributes, status and working files. Strict metadata joins, scope/rename/intent-to-add policy, patch bounds and the single existing retry are unchanged. Temporary directories are removed on success and failure. Added assertions for bytes and physical guard fields (device, inode, size, mode, mtime, ctime), split indexes, attribute normalization, both repository refresh settings, cancellation and mode/intent-to-add metadata/patch agreement; a byte-identical external index replacement must still discard both attempts.
