## Explicit local hunk-review milestone — 4 October 2026

Implemented `dr review mark/list/reset` using explicitly exported, runtime-validated 1.0.0/1.1.0/1.2.0 bundles. Mark requires concrete snapshot and hunk evidence IDs; list/context never mark or create acknowledgment state. Independent strict state/output schemas are version 1.0.0; Git/syntax/candidate evidence schemas and fact IDs remain unchanged. No new dependencies, analyzers, network calls or repository script/test/hook execution were added.

Matching combines stable repository identity, branch/detached/base/scope/comparison policy, immutable before blob/mode/region, raw file lineage, and normalized ordered byte/newline fingerprints. Range presentation, locale and timestamps do not establish identity. New-side line shifts and authoritative Git renames can retain a unique acknowledgment; same-region content edits become changed-since-reviewed only with unique before continuity. Identical/repeated/competing hunks and changed before blobs/contexts remain unseen. An identical edit moving between repeated regions of the same blob also becomes unseen. Reviewed is an explicit human acknowledgment, not correctness, safety or test coverage.

Writers use an exclusive lock and same-directory, flushed temporary file followed by replacement rename; pre-commit abort/failure preserves the old state. A killed writer's temporary content is never promoted. Pending locks are visible in partial read-only listings and block all writes until an operator confirms the writer is stopped. Corrupt/version-incompatible state fails visibly; explicit reset can discard it with a warning and unknown count. Symlink/junction bounds and evidence/state/count limits are enforced. See `docs/review-state.md` and its generated schemas for command semantics, historical snapshots, conservative continuity and recovery.

Patch subprocesses retain a bounded prefix and terminate on overflow.
