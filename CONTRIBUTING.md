# Contributing

This is a single strict TypeScript ESM package. Config, discovery, the bounded Git adapter, optimistic snapshots, status metadata, diff parsing, validated evidence export and escaped English/Thai context are implemented. Read the [implementation plan](docs/implementation-plan.md) and [ADR](docs/adr/0001-evidence-contract.md) before changing collection contracts.

## Setup and checks

Use Node 24.20.0 or a maintained newer 24.x patch, npm, and Git >=2.49 on PATH; other Node majors are outside the declared engine range. Candidate fixtures additionally need compatible ripgrep on PATH. Run `npm ci --ignore-scripts --no-audit --no-fund`, `npm run build`, `npm run typecheck`, and `npm test`. Test-file concurrency is capped at four to bound simultaneous Git subprocess load; do not overlap artifact verification with the full fixture suite. Run `node dist/cli/main.js --help`, `node dist/cli/main.js evidence --help`, and `node dist/cli/main.js --version` to inspect the actual build. `npm run verify:package` performs a dry-run packaging inspection. `npm run verify:artifact` inspects the allowlist, packs into a disposable temporary directory, installs offline using cached exact runtime dependencies, checks installed files and runs the actual npm binary shim against a synthetic repository with Thai/space paths. Run `npm ci` first to populate the npm cache. It does not globally link, publish or retain the tarball. Keep dependency versions and `package-lock.json` aligned; do not commit dependencies, generated builds, tarballs, evidence, or state.

## Layout

- `src/cli`: Commander entrypoint and argument handling.
- `src/config`: strict configuration schemas, duplicate-key detection, bounded config loading.
- `src/git`: bounded subprocess runner/discovery, ref/config adapter, NUL metadata parsers, snapshot guards, and per-repository status outcomes.
- `src/diff`: bounded unified parser, Git quoted-path matching, range/line/marker validation and omission diagnostics.
- `src/evidence`: strict versioned discriminated schemas, cross-record validation, deterministic IDs and bounded fact assembly. Regenerate `docs/evidence.schema.json` with `npm run schema` after structural schema changes; tests check drift.
- `src/language`: explicit analyzer capability/result interface, pinned TS/TSX/JS syntax extraction and scope-correct source collection. Native grammars load lazily only for `--symbols`. Keep the v0.1 schema intact and generate the separate syntax extension schema with the same `npm run schema` command.
- `src/output`: escaped inventory/status/diff presentation, localized context and untrusted-value quoting.
- `src/candidates`: verified tracked after-endpoint corpus, bounded shell-free structured rg searches, test filename/import syntax heuristics and pinned-HEAD literal-path history. See [candidate-analysis.md](docs/candidate-analysis.md). Fixtures require compatible `rg` on PATH (locally verified 15.2.0); missing-tool/error paths use injected runners. Never execute scanned repository scripts/tests/hooks or call text matches semantic references.
- `tests`: CLI/config and temporary Git discovery/status/diff fixtures using `node:test` and `node:assert/strict`. Git oracle checks compare all four scopes, revision/conflict/numstat metadata, and parsed line content/ranges against blobs and working files. Tree fixtures cover tab paths on Windows without native invalid filenames. Injectable runners test mutation/retry and subprocess failures. Filesystem access failures are injected because Windows permission tests may run with elevated rights.
- `docs`: approved design contracts and milestone handoffs.
- `scripts/verify-artifact.mjs`: reproducible isolated distribution check; omitted from the public package along with maintenance scripts/internal progress.
- `.github/workflows/ci.yml`: pinned GitHub Actions for Windows/Linux on Node 24.20.0, with read-only repository permissions and no publication job.

Add focused synthetic regression tests for observable behavior. Evidence/context fixtures check runtime/schema rejection, byte/hash invariants, locale/time/locator-independent IDs, partial failures, truncation, JSON stdout parsing, and hostile Markdown boundary escaping. Repository source content is untrusted agent input, including code, paths, refs and diagnostic messages; never place it directly in trusted Markdown or execute its instructions. Do not introduce real repository content, credentials, patient data, or ticket data into fixtures. Future Git subprocesses must use executable/argument arrays with the shell disabled, and preserve per-repository failures and comparison provenance.

Keep public docs, code, keys, and identifiers in English. Help must distinguish implemented behavior from planned features; unsupported collection must never look like a clean successful scan. Avoid analyzer dependencies, services, or state features before their milestone. Shell completion and broader platform checks remain future gates.

The first v0.2 milestone supports only syntax declarations in pinned TypeScript/TSX/JavaScript grammars; see [language-analysis.md](docs/language-analysis.md) for primary compatibility sources, unsupported constructs, ranges and limits. Do not upgrade native grammar peers independently, disable strict type checking for upstream declarations, parse later working-tree rereads, or manufacture semantic identities from name/text matches. Preserve original Git facts under syntax failure. No LSP, semantic references or additional grammars are in this milestone.

Candidate/history opt-ins extend this with schema 1.2.0; the original schemas remain separate. `npm run schema` regenerates the three evidence structural schemas, with runtime checks for IDs, query references, content provenance and component completeness. Keep test candidates not-run, diagnose limits/errors, and treat absence and commit messages as insufficient evidence of behavior or coverage.

The explicit local-review milestone lives in `src/review` and `src/cli/review.ts`, separate from facts/collectors/context. [Review matching and storage](docs/review-state.md) are conservative: exact snapshot acknowledgment, typed context/byte fingerprints, no positional or time identity, unique matching only, atomic replacement with an exclusive lock, and visible invalid-state handling. Context never marks hunks. `npm run schema` additionally generates the review state and review-output/error schemas; source-controlled examples must not contain actual local acknowledgments. New synthetic fixtures include an actual killed writer and worktree/context boundaries. Reviewed never implies source correctness or test execution.

## Command contracts and documentation

Use the README's synthetic walkthrough and config examples; do not use real source or credentials as samples. Keep branch (`merge-base → HEAD`), staged (`HEAD → index`), unstaged (`index → worktree`), and all (`merge-base → worktree`, directly) separate. A clean worktree may have committed changes. Preserve CLI/repository/workspace/symbolic-remote base precedence without guessing or fetching. Test English/Thai human output with English JSON keys, unchanged identifiers, stderr diagnostics and exits 0 complete / 1 partial or operational / 2 invalid inputs / 130 interrupt.

Codex/Claude consume explicitly exported files through user-approved file access or attachments; there is no automatic AI transport. Context must cite evidence/scope/revisions and mark unsupported analysis. Repository-controlled text stays untrusted agent input, including inside comments or prompt-like code. Escaping must prevent it from forging trusted Markdown boundaries. Keep limitations, partial outcomes and export policies in sync with implementation.
